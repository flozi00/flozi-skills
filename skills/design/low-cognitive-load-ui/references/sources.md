# Low-Cognitive-Load UI — Sources

Research basis (verified 2026-11-23):

- **W3C COGA — Making Content Usable for People with Cognitive and Learning
  Disabilities**
  https://w3.org/TR/coga-usable/design_guide.html
  8 guidelines; patterns for consistency (4.2.3), clear steps (4.2.4),
  recognizable controls (4.2.5), control-content relationship (4.2.6),
  page structure (4.3.3), clear words (4.4.1), stable content (4.5.1).

- **W3C WCAG 2.2 supplemental patterns**
  https://w3.org/WAI/WCAG2/supplemental/patterns/o1p06-control-actions
  https://w3.org/WAI/WCAG2/supplemental/patterns/o3p01-clear-words
  https://w3.org/WAI/WCAG2/supplemental/patterns/o7p02-alternative-content

- **NN/g — Progressive Disclosure (Jakob Nielsen)**
  https://www.nngroup.com/articles/progressive-disclosure/
  Two-level maximum, information scent, right split between initial and
  secondary features, benefits for learnability/efficiency/error rate.

- **Microsoft — Progressive Disclosure Controls**
  https://learn.microsoft.com/en-us/windows/win32/uxguide/ctrl-progressive-disclosure-controls
  Risks: lack of discoverability, lack of stability.

- **Designing for Power Users vs. New Users**
  https://designpixil.com/blog/designing-for-power-users-vs-new-users
  Keyboard shortcuts as respect signal; dismissible onboarding; risks of
  explicit simple/advanced modes.

- **ADHD / neurodiversity UX**
  https://welcomingweb.com/learn/designing-for-neurodiversity-adhd-ux
  https://medium.com/design-bootcamp/beyond-compliance-16-ux-principles-to-truly-include-neurodivergent-users-e7d3ff779665
  Reduced cognitive load, minimal menus, no auto-play/blinking, consistent
  structure, WCAG 2.4.6 / 3.1.5 / 2.2.1.

- **Sensory-friendly design**
  https://www.tiimoapp.com/resource-hub/sensory-design-neurodivergent-accessibility
  Focused settings instead of endless configuration; choice overload as
  cognitive burden; subtle slow animations.
